# ED4 Mobile — Phase 3

현재 체크아웃은 GitHub Desktop + Pages `main /docs` 배포용입니다. [GITHUB_DESKTOP_GUIDE.md](GITHUB_DESKTOP_GUIDE.md)와 [DEPLOY_CHECK_REPORT.md](DEPLOY_CHECK_REPORT.md)를 따르세요. `/ed4-mobile/` base로 `docs/`를 생성하며 RAW 샘플은 배포하지 않습니다. 기존 소스·배포본은 보존했고 GitHub 업로드는 수행하지 않았습니다.

사용자가 보유한 구영웅전설4 DOS ZIP을 브라우저에 등록하는 독립 웹 실행기입니다. 한국어 UI, js-dos v7 계열 DOS 엔진, 프로필/모드별 저장 분리, PWA 오프라인 실행을 구현했습니다.

Phase 2에서는 삭제 상태 유지, 원본 ZIP SHA-256 검증, 모드 충돌·저장 가림 진단, Worker 기반 실행 ZIP 합성, 파일 구조 분석과 진단 내보내기를 추가했습니다.

**구영웅전설4 원본은 포함하지 않으며 실제 게임 실행·한글·음악 호환성은 아직 검증하지 않았습니다.** 동봉한 공개 DOS 테스트 프로그램으로 실행/저장/복원 경로를 검증했습니다.

## Phase 3 추가 기능

가로 전체 화면 우선·방향 잠금 실패 안내, 폴더 등록, RAW 파일/폴더/ZIP 별도 OPFS 보관, DOS 구간 읽기, 선택 곡 PCM 시험 재생, 정적 BAT/드라이버 분석과 진단을 추가했습니다. 음악 없는 실행도 지원합니다. 500 MiB 합성 폴더(본체 68 MiB + RAW 약 432 MiB)를 공개 DOS 프로그램으로 검증했습니다. 실제 ED4 테스트는 사용자의 Galaxy에서만 진행합니다.

현재 단위 76개 / Chrome E2E 17개 통과. [Phase 3 보고서](PHASE3_REPORT.md), [Galaxy 테스트 가이드](ANDROID_TEST_GUIDE.md), [대용량 처리](LARGE_GAME_SUPPORT.md), [RAW 분석](RAW_AUDIO_ANALYSIS.md), [DOS 오디오 호환성](DOS_AUDIO_COMPATIBILITY.md)를 참고하세요. GitHub 업로드·공개 배포는 승인 전 수행하지 않습니다.

## 실행

Node.js 24 LTS 권장. 이 작업 환경에서는 필요한 의존성을 이미 설치했고 `docs/`도 생성했습니다.

```powershell
cd D:\porting\ed4-mobile
npm.cmd run preview
```

브라우저에서 <http://localhost:4173/ed4-mobile/> 접속. HTML 파일을 더블클릭하는 `file://` 방식은 지원하지 않습니다.

새로 설치하거나 소스를 변경한 경우:

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd run preview
```

개발 서버: `npm.cmd run dev` → <http://localhost:5173/ed4-mobile/>. 개발 서버에서는 서비스 워커를 등록하지 않습니다. PWA/오프라인 검사는 반드시 `build` + `preview`에서 수행하세요. 두 주소의 포트가 다르므로 데이터 저장소도 서로 다릅니다.

## 원본 없이 테스트하기

1. **먼저 실행 환경 확인하기**를 누르면 공개 테스트 프로필을 등록합니다.
2. **실행**을 누릅니다. 화면에 `ED4 TEST READY`가 표시됩니다.
3. PC에서 `S`, 모바일에서는 **키보드**를 열고 `S`를 눌러 `SAVE WRITTEN`을 확인합니다.
4. **저장 후 종료** → 재실행 → `L`을 눌러 `ED4_SAVE_OK!`를 확인합니다.
5. **저장 백업**으로 ZIP을 받습니다. 다른 테스트 프로필을 등록하면 저장은 공유되지 않습니다.
6. 상단 **오프라인 준비 완료**를 확인한 뒤 네트워크를 끊고 새로고침하여 재실행합니다.

테스트 프로그램은 이 프로젝트에서 만든 16-bit DOS COM 프로그램입니다. 생성 소스는 `scripts/test-program.mjs`, 배포 ZIP은 빌드 시 만드는 `public/test-program.zip`입니다. CC0-1.0으로 공개 가능합니다.

Phase 2 테스트 키: `D`는 `TEST.SAV` 삭제, `R`은 `RESOURCE.DAT` 변경, `X`는 해당 리소스 삭제입니다. 삭제 후 저장·종료·재실행하여 삭제 유지 여부를 확인할 수 있습니다. `START.BAT`으로도 실행할 수 있습니다.

## 게임 / 모드 등록

- **바닐라**: 원본 ZIP을 선택하고 `.EXE`, `.COM`, `.BAT` 후보 중 실제 시작 파일을 선택합니다.
- **모드 A**: 등록된 원본 ZIP을 선택한 뒤 수정 파일 ZIP을 추가합니다. 중복 파일 목록을 확인해야 등록할 수 있습니다.
- **모드 B**: 수정된 게임 전체 ZIP을 독립 프로필로 등록합니다.
- 모드 프로필의 **수정 ZIP 추가**로 레이어를 추가할 수 있습니다. 실행 설정에서 ↑로 적용 순서를 바꾸거나 제거합니다. 아래 레이어가 나중에 적용됩니다. 원본 바닐라 프로필에는 직접 수정 ZIP을 붙이지 않습니다.
- 적용 순서: **원본 → 수정 ZIP들 → 해당 프로필의 삭제 상태 → 저장 변경분**. 저장 변경분에 실행 파일/데이터 파일이 있으면 그것도 마지막에 적용되며, 원본/모드 파일을 가리는 경로를 실행 전에 표시합니다.
- **파일 구조·충돌 분석**에서 파일 출처, 동일 경로 충돌, 실행 후보와 DOS 8.3 경고를 확인합니다. 레이어 순서 변경·제거 시 실제 내용이 바뀌는 파일을 표시합니다.
- ZIP의 정확한 바이트에 SHA-256을 기록합니다. 원본 버전 ID와 프로필의 요구 원본 버전을 지정할 수 있습니다. 재압축한 ZIP은 내부 파일이 같아도 해시가 달라질 수 있습니다.
- 게임 본체는 IndexedDB, RAW는 OPFS에 보관하며 서버로 보내지 않습니다. 등록된 원본 내용은 덮어쓰지 않습니다. 별도 음악은 버전·상대 경로를 확인한 뒤 프로필에 연결하세요. 여러 프로필이 같은 음악 보관함을 공유할 수 있습니다.
- 일반 ZIP만 지원합니다. `.jsdos` 설정을 가진 번들, 비 ASCII 경로, 상위 경로 탈출, DOS 장치명, 대소문자 중복, 파일/폴더 충돌을 거부합니다. 실행 파일과 그 상위 경로는 DOS 8.3 이름이어야 합니다.
- 본체는 해제 후 256 MiB, 파일당 64 MiB 제한을 유지합니다. 폴더/RAW 분리 경로는 전체 768 MiB, RAW 파일당 128 MiB, 항목 12,000개입니다. 작은 RAW 없는 ZIP은 기존 128 MiB 경로를 사용합니다. 음악은 OPFS에 별도 보관하고 실행 ZIP에서 제외합니다. 기기 메모리 한도에 먼저 도달할 수 있으며 500 MiB 전체가 본체인 자료는 지원하지 않습니다.
- 한글 구동용 배치가 있다면 이를 실행 파일로 선택하세요. 필요한 초기화는 **설정 → 실행 전 DOS 명령**에서 지정합니다. 특정 게임 실행 파일명이나 한글 드라이버를 추측하여 넣지 않았습니다.

## 저장과 복구

게임 내부에서 저장한 다음 **저장 후 종료**를 사용하세요. 런처가 보관하는 것은 DOS 파일시스템의 변경 파일이며 CPU/메모리 순간 상태가 아닙니다. 실행 중 30초 간격과 탭이 숨겨질 때도 변경 파일 저장을 시도하지만, 모바일 강제 종료 직전 저장 완료는 보장되지 않습니다.

- **저장 백업**: 프로필 정보와 파일 변경분을 ZIP으로 내보냅니다. 변경된 게임 리소스가 있으면 포함될 수 있으므로 백업을 게임 세이브만 있는 파일이라고 가정하지 마세요.
- **백업 가져오기**: 같은 프로필 ID의 저장을 교체합니다. 다른 프로필로 실수로 섞어 넣는 것을 차단합니다.
- 브라우저 데이터를 잃었거나 다른 브라우저로 이동할 때: **저장 공간 관리 → 백업에서 프로필 복구** → 원본/수정 ZIP을 각각 **다시 연결**. 기록된 ZIP 해시와 다르면 연결을 거절합니다. 해시가 없는 Phase 1 데이터는 미확인으로 표시되며 첫 재연결 시 사용자 확인을 거쳐 기준 해시를 등록합니다. 이 최초 연결이 과거 ZIP과 같은지는 자동으로 증명할 수 없습니다.
- **게임 데이터 삭제**, **세이브 삭제**, **프로필 삭제**는 구분되어 있습니다. 프로필을 삭제해도 세이브는 관리 화면에서 백업/삭제할 수 있습니다. 공유 중인 원본 ZIP은 관련 프로필을 먼저 정리해야 삭제할 수 있습니다.
- **영구 저장 요청**은 브라우저가 거절할 수 있습니다. 사이트 데이터 수동 삭제를 막아주지는 않습니다.
- 같은 주소에서 두 탭을 동시에 열면 첫 번째 탭만 데이터를 변경합니다. 두 번째 탭은 첫 탭을 닫고 새로고침해야 합니다.

파일 삭제 상태(tombstone)를 프로필별로 기록하여 재실행 때 적용합니다. 기본 저장 규칙 `*.SAV`, `SAVE/`, `SAVES/`는 ED4에서 검증한 규칙이 아니며 설정에서 조정할 수 있습니다. 그 밖의 기존 리소스 변경도 별도 필드에 보존합니다. 전체 원본/수정 파일은 변경하지 않습니다.

Phase 1 저장과 v1 백업은 읽을 수 있습니다. 새 백업은 v2이며 DB 스키마도 2로 올라가므로 Phase 1 앱으로의 다운그레이드는 지원하지 않습니다. 자세한 의미론과 검증 범위는 `SAVE_INTEGRITY_TEST.md`와 `MOD_COMPATIBILITY.md`를 확인하세요.

**진단 내보내기**는 설정·경로·로그·측정치를 JSON으로 저장하며 게임 파일 내용은 포함하지 않습니다. 범용 DOS CPU/메모리/사운드 프리셋은 실험용이고 ED4 전용 확정 설정이 아닙니다.

## 모바일 / PWA

정적 호스팅에 **`docs/` 전체**를 HTTPS로 제공하세요. Android에서 접속 후 **앱 설치** 또는 브라우저 메뉴의 홈 화면 추가를 사용합니다. APK는 필요하지 않습니다. 첫 온라인 캐시가 완료되어야 오프라인 실행할 수 있습니다.

`http://PC의-LAN-IP:4173`은 일반적으로 보안 컨텍스트가 아니어서 PWA·Web Locks·영구 저장 기능을 검증하는 주소로 사용할 수 없습니다. Android 실기기에는 HTTPS 테스트 배포가 필요합니다. 실제 홈 화면 설치는 이번 환경에서 수행하지 않았습니다.

가로 화면에서는 실행 화면과 터치 버튼에 집중한 레이아웃으로 전환됩니다. 방향키, 확인/취소/메뉴, 영문 가상 키보드, 크기/가장자리 간격, 임시 입력키 매핑을 조정할 수 있습니다. 소리는 사용자 클릭 후 활성화됩니다. 매핑 기본값 Enter/Esc/Space는 실제 ED4에서 검증되지 않았습니다.

## 검사

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
npm.cmd audit
```

E2E는 시스템에 설치된 Google Chrome을 headless로 사용하며 별도 브라우저 다운로드가 필요하지 않습니다. `playwright.config.ts`의 `channel`을 로컬 환경에 맞게 바꿀 수 있습니다. 테스트는 공개 테스트 프로그램과 합성 데이터만 사용합니다. Phase 2 결과는 단위 54개, E2E 11개 통과입니다. 상세 결과와 PC 메모리 관측의 한계는 `PHASE2_REPORT.md`를 참고하세요. `PHASE1_REPORT.md`는 당시 기록으로 보존했습니다.

## 구조

```text
src/model.ts       게임 ID / 엔진 ID / 실행 프로필 / 저장 모델
src/archive.ts     ZIP 경로 검사, 레이어 합성, DOSBox 구성
src/importer.ts    ZIP Worker 수명과 시간 제한
src/zip-worker.ts  업로드 ZIP 검사 및 해제
src/storage.ts     IndexedDB 트랜잭션, 독립 저장 공간
src/save-state.ts  삭제 상태, 세이브/리소스 분리
src/integrity.ts   SHA-256, 버전 요구, 이전 데이터 식별
src/compatibility.ts 레이어 충돌 및 변경 영향
src/runtime-worker.ts 실행 ZIP 합성 Worker
src/telemetry.ts   단계별 시간 및 버퍼 관측
src/presets.ts     ED4 미검증 범용 DOS 설정
src/backup.ts      백업 형식, 동일 프로필 복원, 프로필 복구
src/engine.ts      js-dos v7 Worker, Canvas, Web Audio, 저장
public/dos-worker.js 런타임 파일 목록 관측 adapter
src/controls.ts    PC / 터치 키 입력과 해제
src/main.ts        한국어 UI와 작업 흐름
scripts/          에셋 생성, 소스 패키징, 서비스 워커 생성
tests/            단위·저장 테스트 / 실제 Chrome E2E
public/sources/   함께 제공하는 런타임 및 런처 소스
```

`gameId`와 `engineId`, `Engine` 인터페이스를 분리했습니다. 현재 지원 게임과 엔진은 ED4 / js-dos v7 하나뿐입니다. Windows, 신영웅전설3, 영웅전설5, 신영웅전설4 그래픽 연동은 구현하지 않았습니다.

라이선스와 정확한 소스 커밋, 배포 시 포함해야 할 파일은 `THIRD_PARTY_NOTICES.md`를 참고하세요. 공개 원격 배포나 GitHub 업로드는 이번 작업에서 수행하지 않았습니다.
